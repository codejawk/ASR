02

The goal

Put two speech models on a watch — and keep them tiny

Model 1 · ≤ 10 MB

General recognition

Free-form natural language: dictation, messages, questions. Streaming, low latency.

Model 2 · ≤ 5 MB

Commands

"Call mom", "set a timer" — always-on, and understands intent + slots, not just keywords.

Non-negotiables: fully on-device (privacy + offline), streaming (text as you speak), and small enough to fit the memory budget while running on the phone's NPU.

03

Why it's hard

Three constraints shape every decision

Memory

10 + 5 MB resident

Not a compute limit — the chip runs 2B-param models. It's RAM residency, OTA size, a shared OS pool.

Power

Always-on vs duty-cycled

Commands must listen 24/7 at eNPU milliwatts. A 10 MB encoder can't run continuously without draining the battery.

Deployment

int4 on QNN / HTP

Must map to accelerator ops. No exotic kernels, no dynamic loops in the graph.

04

Primer

ASR is a stack — the "head" decides if it fits a watch

audio → log-mel features → encoder → head → text. What determines size & streaming is the head:

HeadStreaming?CostOur use
CTCtriviallycheapest (one linear layer)Model 2

Streaming vs offline is architectural, not tunable — you can't quantize an offline model into a streaming one. That's why Whisper is our teacher, never the on-device model.

05

State of the art · 2025–26

Where the field is — and what's relevant to us

Frontier encoders

SSM / Mamba

O(1) recurrent state, no growing KV cache. Samba-ASR, ConMamba — battery-friendly streaming.

Accuracy / param

Zipformer

The open streaming leader (ICLR 2024). Standard ops → deploys on the NPU today.

Teachers

Whisper / Parakeet

Whisper-large 1.5B (WER ~5–7%); Parakeet-TDT-0.6B faster on English. Used to label data.

Key datapoint: aggressively compressed edge ASR in the literature is still ~670 MB (Microsoft, int4). Our 10 MB target is only reachable by designing small + distilling + int4, not by shrinking a big model.

06

Our approach

Distil two specialists from one teacher

  • 01Distillation-first is the real lever. At ~10M params, a large teacher is worth 20–40% relative WER; a fancier encoder is worth ~2%. Optimize what moves.
  • 02Right head per job. Transducer for free dictation (Model 1); CTC + intent/slot for commands (Model 2).
  • 03Share knowledge, not weights. The always-on power budget forces two separate models — siblings distilled from one teacher, not one shared network.

08

Model 1 · ≤ 10 MB

General recognition — the budget is the encoder

Streaming RNN-T transducer + aux CTC. Cache-aware chunked encoding (every frame encoded once). The encoder is 85% of the budget, so encoder choice is the size decision.

int4-mixed = encoder int4 / joiner int8 / decoder fp16. MB, weights.

09

Model 2 · ≤ 5 MB · used wisely

Commands that understand, not just match

A good command model does spoken-language understanding — intent + slots — on the wrist, no cloud NLU.

said"set a timer for five minutes"  →  { intent: timer, number: five, unit: minutes }
said"call mom"  →  { intent: call, contact: mom }

Head = Conformer-CTC + keyword FST + intent/slot. Add a command by typing text — no retraining. SLU model ≈ 0.1 MB.

15

Proof 3 — engineering rigor

Real bugs found and fixed — this is a working system

✓Tokenizer/label mismatch. Whisper's punctuation became "unknown" tokens — targets were unlearnable. Fixed with text normalization + tokenizer trained on the same text.
✓Missing LR warmup. The transducer loss oscillated and never converged on long utterances. Added warmup + cosine decay.
✓GPU RNN-T length mismatch. Encoder lengths were approximate; the CUDA kernel rejected them. Computed the exact subsampled length.
✓FLAC loading + fine-tune warm-start. Added real-audio loaders and --init so models can be personalized.
16

The honest finding

General ASR needs data — and we proved that too

We trained the 10 MB general model on a 2-hour subset. It scored WER 1.0 — it learned only silence. The CTC head stayed near random (5.6 ≈ log of the vocab).

2h datageneral model → ''  (emits nothing — the data wall)
same codesynthetic data → WER 0.00  ·  commands → WER 0.20

Why this matters: it's not a bug — the machinery is correct (WER 0 on synthetic; Whisper 0.05 on the same audio). General ASR from scratch needs ~100× more data. That defines exactly what "how we get there" requires.

Built · on-device

Proof 4 — personalization

Adapt to a real voice with a handful of recordings

The TTS-trained model garbles a real voice (synthetic→real gap). The fix is few-shot: record ~40 clips of your own voice, fine-tune from the existing model (--init), and it recognizes you — all on the Mac, in minutes.

beforeyour voice → 'set a the me tos'  (never heard a human)
after fine-tuneyour voice → recognized  (personalized)

On-device personalization is a real product feature — and the tooling exists in the repo (record_commands.py + --init).

How we get there

From proven pipeline to shipped model

01Data. Commercial: Loquacious (25k h) + wrist recordings. Research: SLURP / Speech Commands for real command voices.
02Label + distil. Whisper-large / Parakeet pseudo-labels → train the Zipformer transducer student (the pipeline already runs).
03Compress. int4 QAT + structured pruning → ≤ 10 MB, deployable ops.
04Personalize. On-device fine-tune on the user's voice (already prototyped).
05Deploy. 3-graph static ONNX → QNN context binary for the Wear-Elite Hexagon.

Owned risks

What we'd watch — stated plainly

!Data quantity. General ASR needs 100s of hours; we proved the wall. Mitigation: the distillation + big-corpus plan.
!Mamba not on the NPU yet. Selective-scan has no QNN kernel — ship Conformer/Zipformer, keep Mamba as research.
!Dataset licensing. GigaSpeech & SLURP are non-commercial. Use Loquacious for product; clear licenses with legal.
!Evaluate on real wrist audio, not LibriSpeech, before any accuracy claim.
