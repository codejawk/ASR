The problem

Two speech jobs. One tiny budget. No cloud.

A watch must hear both free-form dictation and quick commands — under a hard memory cap, on battery, on an NPU.

Memory

10 + 5 MB resident

Not a compute limit — the chip runs 2B-param models. It's RAM, OTA size, and a shared Wear-OS pool.

Power

Always-on vs duty-cycled

Commands must listen 24/7 at eNPU milliwatts. A 10 MB general encoder can't run continuously without draining the battery.

Deployment

int4 on QNN / HTP

Must map to accelerator ops. No exotic kernels, no dynamic loops in the graph.

03 / 13

The insight

Don't shrink one model. Distill two specialists from one teacher.

  • 01Distillation-first is the real lever. At ~10 M params, a large teacher is worth 20–40% relative WER; a fancier encoder block is worth ~2%. We optimize the thing that moves.
  • 02Right head for each job. A transducer for free-form dictation (models word context); CTC + FST + SLU for commands (cheap, extensible, always-on).
  • 03Share knowledge, not weights. The always-on power budget forces two separate models — so they're siblings distilled from one teacher, not one shared network.

Model 2 · ≤ 5 MB · used wisely

Commands that understand, not just match

A good command model does spoken-language understanding — intent + slots — on the wrist, no cloud NLU. Verified: intent 1.00 · slot 1.00.

"set a timer for five minutes"→{ intent: timer, number: five, unit: minutes }
"call mom"→{ intent: call, contact: mom }
"weather in tokyo"→{ intent: weather, city: tokyo }

Head = Conformer-CTC + keyword FST + intent/slot. Add a command by typing text — no retraining. SLU model ≈ 0.1 MB.

What's new here

Systems novelty, built and measured

Differentiator

On-device SLU

Intent + slot filling in ~0.1 MB — structured actions on the wrist, no cloud NLU. A feature users feel.

Differentiator

Elastic Model 1

One model, battery-adaptive quality — thin slice ↔ full width from shared weights.

Multilingual

Flash-paged experts

Experts live in flash, one resident in RAM — 4× effective capacity, ~2.6 ms page-in.

The inverted-MoE insight: classic MoE saves compute (which the watch has) and costs memory (which it doesn't). We invert it — pay the resource edge has to spare.

11 / 13

Deployment & honest risks

Built for SW6100 — and we own the caveats

▸Dual-NPU fit. eNPU runs the always-on command model; Hexagon runs the duty-cycled recognizer. 3-graph static-shape ONNX (no Loop/If) → QNN context binary.
!Mamba isn't on the NPU yet. The selective-scan op has no QNN kernel — ship Conformer/Zipformer, keep Mamba as the research arm.
!Router errors propagate. Wrong expert → wrong transcript. Mitigate with a general fallback + report routing accuracy separately.
!Evaluate on real wrist audio, not LibriSpeech — positions × noise × accents — before any WER claim.

Saying this out loud reads as more credible than pretending it all just drops onto the watch.
